# 数据格式契约 v2（清洗）

上游只有一个出口：一张 35 格的表格（7 天 × 5 大节）。本文件规定它如何变成可入库、可查询的事实。

本文只定义清洗规则；数据存储结构与查询 API 的规范另行设计。

## 上游原生事实（不可协商）

细节见 `../upstream.md`，这里只列对清洗有约束的条目：

- 周查询：`POST /jsxsd/kbxx/jsjy_query2`，`typewhere=jszq`、`xnxqh=<学期>`、`jxlbh=<白名单教学楼编号>`、`jsmc_mh=`（留空）、`zc = zc2 = <周次>`、`xq=1`、`xq2=7`；**不传** `jc`/`jc2`/`jszt`。一栋白名单楼一次请求。禁止 `jxlbh` 留空，也禁止把楼名写入 `jsmc_mh`。
- `jxlbh` 留空时一次返回约 2079 行、9.41 MB、每行 35 格，约 1 秒；这是探测事实，不是采集请求。行内的 `jsbh` 在探测期全部唯一。
- 表头的 `td[tdvalue]` 共 35 个，按 7 天切成 7 组，每组顺序固定为 `0102` / `030405` / `0607` / `0809` / `101112`——**表头本身就是大节编码**，12 个小节是由它推出来的。
- 全学期范围（`zc=1..20`）返回聚合矩阵，无法拆回逐周，所以**必须按周请求**。
- 房名一律带容量片段 `(n/N)`；规范化后仍可能有同名不同 `jsbh`，`jsbh` 是唯一身份。
- 采集范围是管理员配置的教学楼白名单：逐楼带 `jxlbh` 请求，房间记下该次请求的楼。白名单为空则本轮失败。查询只扫已入库房间，不再做第二次楼过滤。详见 `../decisions/2026-10-09-keep-teacher-status-api.md`。

## 清洗分层

| # | 层 | 输入 | 输出 | 不变量 / 失败条件 |
|---|---|---|---|---|
| 1 | fetch | 已登录会话 + 参数 | HTTP 响应、`fetched_at`、`page_sha256` | 非 200 → 失败；页面含「用户登录」或「非法访问」→ 全局失败 |
| 2 | parse | 响应 HTML | 行：`jsbh`、`name_raw`、35 格原文 | 只解析 `table#dataList`；`td[tdvalue]` 必须恰 35 个且块序正确；每个数据行必须 36 个 `td`；`jsbh` 按 `<tr jsbh>` → 行内 checkbox `value` → 首列首个带 `value` 的 input 取值；三者皆空或同一响应内重复 → 结构失败 |
| 3 | normalize | `name_raw` | `name`（规范化展示名） | NFKC → 反复删除容量片段 → 压缩空白并去首尾；方位、校区等其他括号保留 |
| 4 | classify | 35 格原文 + 分类表 | 每格 `state_key`，必要时 `raw_text` | 按空白切词；整词先查表；整词未收录但每字符皆已知且长度 > 1 → 复合；多词或复合词 → `composite`；任一字符不在表内 → `unknown`，**不阻断发布** |
| 5 | expand | 5 大节格 | 7 × 12 节点状态 | **断言同一大节内各节点状态相同**；不一致 → 结构失败（这是"作息表变了"的信号，不允许自动适配） |
| 6 | observe | 以上 | 观测事实 | 一间房 × 一周 × 一天 × 一个节次恰一行 |
| 7 | validate | 本次候选 + 上一版 | 校验结果 | 同一 `jsbh` 归属两栋楼则阻断发布。不按房间总数变化阻断。未知只计数 |
| 8 | publish | 候选集 | 一次发布 | 单事务写入；发布与版本规则另行设计 |

## 状态字典（种子值）

`state_key` 是语义键，含义由 `dict_version` 决定。符号的码点不得规范化成 ASCII（`Ｊ`/`Ｘ`/`Ｇ`/`Ｌ` 是全角拉丁字母，`Κ` 是希腊大写 Kappa）。

| `state_key` | label | available | 上游符号 |
|---|---|---|---|
| `class` | 正常上课 | 否 | `◆` U+25C6 |
| `borrowed` | 借用 | 否 | `Ｊ` U+FF2A |
| `locked` | 锁定 | 否 | `Ｘ` U+FF38 |
| `exam` | 考试 | 否 | `Κ` U+039A |
| `free` | 空闲 | **是** | 空单元格、`空闲` |
| `fixed_reschedule` | 固定调课 | 否 | `Ｇ` U+FF27 |
| `temp_reschedule` | 临时调课 | 否 | `Ｌ` U+FF2C |
| `fully_free` | 完全空闲 | **是** | `完全空闲` |
| `cross_mode` | 跨模式占用 | 否 | `M` U+004D |
| `composite` | 复合占用 | 否 | 多个已收录符号的组合（原文本进 `raw_text`） |
| `unknown` | 未知 | 否 | 未收录文本（原文本进 `raw_text`） |

可用集合由字典的 `available` 给出，**只有 `free` 与 `fully_free`**。`unknown` 与 `composite` 一律不可用：不把未知当空闲。

## 字段语义（要点）

- **身份**：房间唯一身份是 `jsbh`；展示名可以重复，不作主键，同名房间不合并。
- **节次轴**：`axis_version` 记录"12 节点 ↔ 5 大节"的映射。上游块集合变化 → 造新版本并阻断等人工确认，而不是自动适配；旧数据因为带着自己的 `axis_version`，永远可解释。
- **日历**：每周的周一绝对日期入库，时区固定 `Asia/Shanghai`；消费方不再自己实现周次换算。
- **来源与质量**：只存请求参数、`fetched_at`、`page_sha256` 与汇总计数（`unknown_cells`、`composite_cells`）；**不存原始 HTML**，不存账号、Cookie、Token、验证码。

## 配置与运行（WebUI）

- 业务设置一律由 WebUI 管理面板写入数据库配置，采集器与查询服务从库读取，不再走环境变量：`account_username`/`account_password`（教务账号）、`feishu_webhook_url`/`feishu_secret`（飞书告警）、`cron_expr`（采集调度 cron）、`ocr_base_url`（ddddocr-fastapi 地址）。
- 采集时间由 `cron_expr` 驱动；调度器归属（采集器内置 vs 服务端触发）在实现 Spec 里定。
- 采集锁、运行状态与告警去重、发布验收都由后端内部 + 数据库维护，不再需要 `COLLECTOR_STATE_DIR` 与 `PUBLISH_BASE_URL`。
- 验证码识别：图片转 base64，POST `{ocr_base_url}/ocr`（表单字段 `image`），响应 `{"code":200,"message":"Success","data":"<文本>"}`，以 `code=200` 判定成功（细节见 `../upstream.md`）。


## 为什么不那样

- **不按 5 大节存**：12 小节是超集，且查询侧本来就以节点区间表述；块归属用 `axis_version` 与解析期断言补回来（见 `README.md` 决定表）。
- **不用整数状态 ID**：整数需要查表才能读；字典改版时，旧数据会被静默重新解释。
- **不让未知符号阻断发布**：那会把"上游新增一个符号"升级成"整个学期没有数据"；改为降级、计数、告警。
- **不丢弃原始名**：某一周矩阵可能请求失败。失败不得抹掉上一轮已经收下的房名。该周是否空闲改由明细范围派生，派生失败则该周保持未知，不当成空闲。
- **不拉全校再过滤**：楼名关键词会漏掉行政归属该楼、房名不含楼名的教室。范围必须由请求的 `jxlbh` 决定，不能先空参数拉取再在本地丢掉。
