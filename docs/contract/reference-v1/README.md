# reference-v1（旧契约，不是基线）

这些文件是上一版设计的契约，保留只为考古：追问"当初为什么把 12 小节展开写进 schema""旧的四个 GET 长什么样""客户端认哪些错误码"时才读它们。

- `schemas/`：`manifest` / `snapshot` / `config` 三份 JSON Schema。主要问题是把上游原生的大节粒度（5）展开成 12 小节之后**写进了规范**，且状态存成需要查表才能读的整数 ID。
- `api/`：旧前端的响应类型、端点封装与客户端错误码枚举。四个只读 GET 的旧载荷形状与 `code` 取值都在这里。

现行基线在上一层目录：`data-format.v2.md`（清洗）、`db.v2.sql`（canonical 表结构）、`api.v2.md`（查询）。两版之间的取舍记录在 `../README.md` 的设计决定表里。

**不要在这些文件上继续演进**：它们不参与任何校验，也不作为实现依据。
