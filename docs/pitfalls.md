# 重写前已确认的技术细节与坑点

- 日期：2026-10-23
- 来源：教师账号只读探测、当前代码、旧实现快照与旧文档核对
- 用途：重写 PRD 与实现时快速查结论；不含账号、密码、Cookie、原始 HTML
- 权威：产品口径以 [docs/prd.md](prd.md) 为准；本文补充证据、坑点与旧结论核对
- 请求/响应结构：[docs/upstream-api.md](upstream-api.md)

## 1. 登录

- **不是 CAS。** 当前入口是强智教师端直登：登录页 `GET /`，表单提交到 `/Logon.do?method=logonLdap`。旧 `docs/upstream.md` 的 CAS 描述已被实测推翻。
- 直登步骤：`GET /` → `GET /verifycode.servlet` → `POST /Logon.do?method=logon&flag=sess` 取 `scode#sxh` → 按 `username%%%password` 与 `sxh` 插 `scode` 生成 `encoded` → `POST /Logon.do?method=logonLdap`，`userAccount`/`userPassword` 留空，`RANDOMCODE` 填验证码。
- 验证码是 **80×40 JPEG**，不是 PNG。OCR 走 ddddocr-fastapi；服务异常也可能返回 HTTP 200，必须看响应 `code=200`。
- 登录成功判据：响应含“正在登录”/`location`/“教学一体化服务平台”，再 `GET /jsxsd/framework/jsMain.jsp` 校验“教学一体化服务平台”。
- 密码错误立即失败，不重试；验证码错误换新图重试，最多 3 次。
- **单会话坑**：同一教师账号在别处登录会让当前会话失效。探测中多次被踢回登录页，表现为业务页正文含“用户登录”。重写时采集进程只保持一个会话，不要并行登录；管理面板不要复用采集会话去重新登录；一次性排障脚本不要和采集同时登录。
- 会话失效标记：`用户登录`、`非法访问`；重登录一次后再跑当前任务。
- 账号是教师账号；不存教师姓名/工号，不把账号写进文档、日志或测试夹具。

## 2. 学期与周历

- 学期页 `GET /jsxsd/kbxx/jsjy_query`，正文匹配 `\d{4}-\d{4}-\d+`；取不到就失败，不猜学期。
- 周历页 `POST /jsxsd/framework/main_index_loadkb.jsp`，表单 `rq=YYYY-MM-DD`；实测正文含 `第5周 /16周`。`GET` 带 `rq` 也能拿到，重写固定用 POST。
- 解析式要兼容“第 X 周 / Y 周”和“第 X 周 / 共 Y 周”，即 `共` 与空白可有可无。
- `jsMain_new.jsp?t1=1` 也含同一句周次，但当前选择的是 `main_index_loadkb.jsp`；不要两处混用。
- 学期页还带 `input#kbjcmsid`（节次模式 id），明细请求必须带；这个值不是常量，不能写死。
- 非教学周或文本缺失 → 本轮失败，不写半截周历，不发布。
- 第 1 周周一 = 采样日所在周周一 − 7×(X−1)；生成第 1…Y 周全部周一，日期按 `Asia/Shanghai`。

## 3. 矩阵解析

- 真实页面在 `table#dataList` 前还有一个 `table#dataListHeader`。旧正则 `<table ... dataList ...>` 会把 `dataListHeader` 当成目标表，解析报“表里没有表头行”。**必须按 id 精确选择**；现在用 goquery `doc.Find("table#dataList")`。
- 表头行有 **36 个 td**，其中 **35 个带 `tdvalue`**，第一个房间列不带；35 个块编码按天重复 5 大节。
- 数据行也是 **36 个 td**：1 个房间列 + 35 个状态格。
- `jsbh` 取值顺序：`tr[jsbh]` → 行内 `input[type=checkbox]` 的 `value` → 首列第一个 `input[value]`；都取不到 → 结构失败。
- 同一响应内重复 `jsbh` → 结构失败；不要挑一行留下。
- 状态原文：`◆`、`Ｊ`、`Ｘ`、`Κ`、`Ｇ`、`Ｌ`、`M`、`空闲`、空白；`Ｊ`/`Ｘ`/`Ｇ`/`Ｌ` 是全角字母，`Κ` 是希腊 Kappa，码点不能规范化成 ASCII。
- 空白格 = `free`；多个已知符号组合（如 `◆Ｊ`）= `composite`；未收录文本 = `unknown`。`unknown`/`composite` 都不可用，但不阻断发布，原文进 `raw_text`。
- **“完全空闲”不会出现在格子里**；不要按这个文本做映射。
- 房名：NFKC → 反复删 `(n/N)` / `（n/N）` → 压缩空白；方位/校区括号保留；`jsbh` 才是唯一身份。
- 现有合成夹具没有 `dataListHeader`，所以旧测试发现不了误匹配；重写必须补这个结构的回归用例。

## 4. 占用明细

- **`table#tab1` 只是标题表**，里面只有“教室占用情况”一行。字段行在页面下半部的嵌套表格里，每行三列“标签 / 空列 / 值”，标签带全角冒号（`教室状态：`、`课程：`、`周次：`、`时间标志：`）。
- 旧解析器按 `table#tab1` 找字段，会**静默返回空列表**，不是报错；这是最隐蔽的坑之一。重写改为扫描整页 `tr`，只认三列且标签去掉冒号后属于四个字段的行。
- 明细请求：`GET /jsxsd/kbxx/jsjy_jszyqk`，参数 `xnxqh`、`jsbh`、`kcsj=<星期><大节>`、`xq=<星期>`、`typewhere=jszq`，起止参数留空，`type=add`，`kbjcmsid=<学期页 id>`。
- 只存：`教室状态`、`课程`、`周次`、`时间标志`；申请人、任课教师、备注、教室、时间、节次一律丢弃，不存原始 HTML。
- 同一格可能有多条记录；以 `教室状态` 开始分条，按行顺序保留。
- 没有占用记录时页面仍保留 `table#tab1` 标题，字段行为空；返回空列表。连 `table#tab1` 都没有才按结构失败。
- 真实弹窗实测解析结果（不含人名）：`教室状态=正常上课`、`课程=概率论与数理统计`、`周次=1-16`、`时间标志=单双周`。
- 状态名通过 `dict_state.label` 换语义键；标签未收录 → `unknown`，不阻断。

## 5. 完全空闲与可用性

- 教务的“完全空闲”（`jszt=8`）是**房间级、按查询范围**的筛选：所选周次、星期、节次范围内整间教室全空才返回。
- 矩阵单元格只有空白，没有“完全空闲”文字；空白就是 `free`。
- 实测：曲阜 26 栋楼全学期聚合矩阵里“完全空闲”出现 0 次；旧 2025-2026-3 四周快照状态 8 出现 0 次。
- `jszt=8` 实测：Q03 第 5 周 53 间中 49 间整周全空；Q10 第 5 周 0 间；Q06 房间 0008 第 5 周全空但全学期不空，`jszt=8` 只在第 5 周返回它。
- 旧采集器把状态 5（空闲）和 8（完全空闲）都标 `available`；旧线上找空教室直接发 `jszt=8` 让教务筛。新实现不需要存房间级状态：查询侧对所选区间做“每节都可用”聚合即可。
- `dict_symbol` 不登记“完全空闲”；`dict_state.fully_free` 只作查询/展示标签。迁移 `0005` 删除旧符号；`0003` 已执行，不能改。
- 当前代码的 `available` 写死在 `IsUsable()`（只有 free/fully_free），没有读 `dict_state.available`；重写要按字典投影，避免字典改版后查询口径漂移。
- 不要把未知当空闲：`unknown`/`composite` 一律 `available=false`。

## 6. 发布与数据一致性

- 当前代码要求 `done == total` 才发布；但 2026-10-09 的周六全量决策允许过去周矩阵失败后由明细派生。这两条冲突。PRD 的结论是分层：
  - **必需**：当前周及未来周的周矩阵。失败 → 本轮失败，不发布。
  - **可选**：过去周矩阵、聚合矩阵、占用明细。失败 → 记录，继续；发布标 `partial`。
  - 理由：公开查询只覆盖 `date_offset 0..10`，过去的周不会出现在公开查询里；可用性由当前/未来周矩阵决定，明细只作说明。
- 当前代码的 `collect_run_week` 与 `page_sha256`/`fetched_at` 没有真正写入；`collect_run` 的 `weeks_total`、`rooms_total`、`unknown_cells`、`composite_cells`、`release_id` 也没有回写，`FinishSyncRun` 只更新状态和错误。重写必须补上。
- `collect_run.release_id` 如果直接 `REFERENCES release(release_id)`，删除更早 release 时会被外键挡住；重写用 `ON DELETE SET NULL`。
- 进程崩溃会留下 `running` 轮次；启动时把超过 2 小时的 `running` 标 `failed`（`error_code=stale_run`），否则永久锁死。
- 房间目录在采集过程中 Upsert，不参与发布事务；失败轮不抹掉已收房名；同一 `jsbh` 本轮归属两栋楼 → 整轮停止。
- 当前 `derived` 用“本轮有哪些周矩阵”的全局周集合判断；重写应按“该房间在该周是否有矩阵行”判断，才能给缺行的房间补派生。
- 发布单事务：写 release（非 current）→ 观测 → 明细 → 降原 current → 抬新 current → 删除 current/previous 之外版本；任一步失败回滚，原 current 不动。
- `unknown_cells`/`composite_cells` 按大节格计数（房 × 周 × 天 × 大节），同一大节展开的 2–3 个小节不重复计数。

## 7. 容量与请求

- 2026-10-23 实测：学期 `2026-2027-1`，第 5 周 / 共 16 周；曲阜 26 栋楼，日照 11 栋。
- Q10 综合教学楼第 5 周：30 行 × 35 格；`◆` 345、`Ｊ` 114、空白 591。
- 旧决策实测全校有内容格子约 8516 个；按每秒 2 次，明细约 71 分钟；各周矩阵 26×16≈416 次，约 3.5 分钟。
- 相邻请求至少 500ms（每秒至多 2 次）；单次最多 3 次重试；不设 15 分钟整轮上限；必须断点续传。
- 16 周约 2.8–4M 观测行/版本；保留 current + previous 两版；发布按批 COPY。

## 8. 安全与隐私

- 不存原始 HTML、账号、Cookie、Token、验证码、申请人、任课教师。
- 业务秘密（教务密码、飞书 webhook/secret）加密存库；`SETTINGS_ENCRYPTION_KEY` 与数据库备份一起保管，丢失只能重新录入。
- 管理员密码只走 `ADMIN_PASSWORD`；会话用签名 Cookie + CSRF；管理接口不暴露给公开用户。
- 探测过程只做登录与只读查询；临时 Cookie、验证码、页面样本都放在 `/tmp` 并已清理；仓库与文档不含账号/密码。
- 公开查询只读本地库；采集/手动同步不挂公开路由。

## 10. 重写硬提醒

- HTML 只用 goquery（v1.13.0）解析，不再用正则抠结构；正则只用于纯文本（学期、周次、房名容量片段）。
- 测试必须包含：`dataListHeader` 在前、表头 36 td/35 tdvalue、数据行 36 td、`jsbh` 三种来源、明细标题表 + 嵌套三列 + 全角冒号。
- 真实页面样本不进 git；用脱敏/手写夹具锁定结构。
- 登录只保持一个会话，避免单会话互踢。
- 明细解析失败不能当“没有占用”；`tab1` 缺失才结构失败，有 `tab1` 无字段行才是空。
- 发布门槛、`partial` 状态、过期 `running` 清理、`release` 外键删除行为按 PRD 实现。
- 旧文档只作历史与排障输入；与 `docs/prd.md` 冲突时以 PRD 为准。
