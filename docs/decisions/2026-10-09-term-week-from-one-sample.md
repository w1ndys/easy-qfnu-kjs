# 采样一次生成学期周历，查询用日期偏移查本地表

## Background

查询要的是某一天属于本学期第几周、星期几。库里的观测按学期、周次、星期、节次存放。前端不该传周次，查询也不该为每次换算去登录教务系统。

`POST /jsxsd/framework/main_index_loadkb.jsp`，表单字段 `rq=<YYYY-MM-DD>`，能在当前会话里给出该日期的周次。实测 `rq=2026-10-30` 的响应不是结构化周次接口，周次只出现在一句脚本里：`第6周/16周`。同页其余内容是当前登录人的个人课表，不入库。学期编号不在这页。别的学期和寒暑假没有样本。

## Options

### 选项一：每次查询都请求教务系统换算周次

公开查询带会话调用 `main_index_loadkb.jsp`。日期一变就有上游答案。

### 选项二：只存一个锚点，查询时现算

库里留采样日期、周次和总周数。每次查询用天数差推算。

### 选项三：采样一次，生成全部周一日期，查询只查本地表（已选）

采集器对一个已知日期请求一次，解析「第 X 周 / 共 Y 周」，反推第 1 周周一，写入 `term_week`。查询用 `date_offset` 得到目标日期，再按已有覆盖规则查表。

## Decision

采用选项三。

- 当前学期编号仍从 `GET /jsxsd/kbxx/jsjy_query` 读取。周次和总周数改从 `main_index_loadkb.jsp` 的「第 X 周 / 共 Y 周」读取，不再用 `jsMain_new.jsp` 做周历来源。
- 采样日期由采集器在 `Asia/Shanghai` 取当天，并作为 `rq` 发出。星期几由这个日期本地计算，周一是 1，周日是 7。
- 第 1 周周一这样得到：采样日所在周的周一 = 采样日期减去（星期几 - 1）天；第 1 周周一 = 该周一减去（周次 - 1）× 7 天。第 n 周周一 = 第 1 周周一加上（n - 1）× 7 天，n 从 1 到总周数。
- 前提是教学周连续，且每一周都是周一到周日。解析不到「第 X 周 / 共 Y 周」，或 X、Y 不是正整数，或 X 大于 Y，本轮失败，不写半截周历。
- 生成的行写入 `term_week`，`in_calendar=true`。查询不调用这个接口，也不用「今天是第几周」重新推算。
- 前端仍传 `date_offset`。服务端用 `Asia/Shanghai` 的今天加上偏移，得到目标日期。周次和星期由 `ResolveCalendar` 在 `term_week` 里查找。找不到覆盖行就是不在教学周。
- 个人课表 HTML 不解析、不入库。响应里只取那一句周次文本。

## Reasoning

- 星期几可以由日期直接得到。周次不能，因为第 1 周从哪天开始本地不知道。一次带日期的采样就包含了这个起点。
- 今天会变，学期起点不会变。把推算结果落成周一日期后，查询与采样日无关。
- 查询路径已经按 `term_week` 覆盖查找。生成这张表，比改查询算法的面更小。
- 每次查询打教务系统会打破「查询不登录教务」，也会把个人课表页卷进公开接口。

## Trade-offs Accepted

- 周中抽周、或某一周不是周一到周日时，这套推算会错。出现这种校历时再改周历来源，不在查询时现算补救。
- `main_index_loadkb.jsp` 只在当前会话的当前学期验证过一次。采集器必须校验标题和周次文本，不能把登录页或个人课表当成周历。
- 选项一、选项二被否。选项二和选项三的算术相同，但现算会把锚点有效期带进每次查询。
