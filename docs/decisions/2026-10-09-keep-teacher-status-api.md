# 仍走教师端状态接口，采集按教学楼白名单逐楼请求

## Background

空教室的上游是教师端 `POST /jsxsd/kbxx/jsjy_query2`。学生端课表接口虽然已经补全，但不能替代它：学生端只返回本学期有正常上课的教室，借用和锁定显示为空白，响应里也没有 `jsbh`。

教师端全库很吵。2026-10-03 曾决定取消白名单、空参数拉全校。这个决定带来的是用不到的楼，不是「状态种类太多」。同日先写过一版「入库全量、查询时按教室类型过滤」的草稿，当天在写进契约前撤回：过滤要发生在采集请求上，不能先拉全校再在结果里丢。

实测：选中教学楼「老干部楼」能返回「软件测试实验室」这类行政上属于该楼、房名却不含楼名的教室；用关键词「老干部楼」搜不到这些教室。楼名和房名前缀不是同一套。

## Options

### 选项一：改走学生端课表接口

采集目标换成 `kbxx_classroom_ifr`，用「本学期有没有课」代替白名单。

### 选项二：仍拉全校，查询或入库后再按楼丢掉

`jxlbh` 留空，拿到全校行之后再滤。请求次数少，但采进来的集合不是白名单本身。

### 选项三：管理员配置教学楼白名单，采集逐楼请求（已选）

后台配置要采集的教学楼。每一周、每一栋白名单楼单独请求，参数用该楼的 `jxlbh`。房间记下这次请求所属的楼。请求次数上去，同步变慢，这个代价接受。

## Decision

采用选项三。上游仍是 `jsjy_query2`，不换学生端。

- 白名单的配置单位是教学楼，不是单间教室，也不是教室类型。管理员在 WebUI 里从教学楼字典选择，写入数据库配置。每条至少有 `jxlbh`（字典的 `dm`）和展示名（`dmmc`）。
- 周采集对白名单里的每一栋楼发一次请求：`jxlbh` 设为该楼编号，`jsmc_mh` 留空。禁止把教学楼名称写入 `jsmc_mh`。禁止 `jxlbh` 留空拉全校，再在本地过滤。
- 白名单为空时本轮失败并告警，不得退回全校请求。
- 状态行上没有教学楼。房间的所属楼取自返回它的那次请求，入库时写下 `jxlbh` 和当时的展示名。身份仍是 `jsbh`。
- 同一轮里同一个 `jsbh` 若出现在两栋白名单楼的结果中，本轮失败，不挑一栋覆盖。
- 选中的楼会带上该楼行政范围内的全部房间，包括房名不含楼名的教室，也包括这栋楼里的办公室、实验室。不用教室类型再砍一刀。
- 查询只扫已入库的房间，不再做第二次楼过滤。借用、锁定、考试等状态照旧保留。
- 多次请求拖慢同步，接受。周与周之间、楼与楼之间仍遵守既有的间隔和整轮时限；时限不够时先失败告警，不改成空参数全校请求。

## Reasoning

- 学生端会丢掉全学期没课的真教室，并把借用格显示成空白。换接口解决不了「少收几栋楼」。
- 关键词搜楼名会漏掉行政归属该楼、房名不含楼名的教室。老干部楼与「软件测试实验室」就是这个缺口。能闭合这个缺口的是教学楼下拉的 `jxlbh`，不是 `jsmc_mh`。
- 先拉全校再过滤，库里的采集范围和白名单不是同一件事，也和「不要空字符串」相反。
- 所属楼必须随请求记下。状态行不带 `jxlbh`，事后不能从房名反推。

## Trade-offs Accepted

- 每一周的上游请求数从 1 次变成白名单楼栋数。同步更慢。不为此改回空参数全校请求。
- 白名单楼里的办公室、实验室会入库。降噪粒度是楼，不是房间类型。
- 改白名单后，新楼要等下一轮采集才出现；从名单去掉的楼不再更新，已入库的旧观测留到发布策略处理，不在本决定里发明删除规则。
- 选项一、选项二被否。选项二尤其不能用「本地过滤结果一样」来翻案。
- `room` 的所属楼字段还没进已执行的 `0001_init.sql`。本决定不改那份已落地迁移；字段随采集器实现一起加迁移。
