# collect-pipeline 实施计划

- [ ] 1. parser 矩阵解析
  - 按 `dataList` 精确定位目标表，避开同名前缀表
  - 校验 35 个状态格集合与顺序、数据行单元格数量一致、响应内重复房号判结构失败
  - 房号三来源顺序：行属性 → 行内复选框 → 首列输入框
- [ ] 2. parser 明细、周历与学期文本解析
  - 明细只采纳三列且标签去冒号后属于四字段的行；同一格多条按顺序保留
  - 有标题表无字段行视为「该格无说明」且解析成功；连标题表都没有才结构失败
  - 周历与学期文本正则解析，兼容「共」与空白
- [ ] 3. clean 状态分类与可用性投影
  - 整词命中字典 → 语义键；空文本 → 空闲；多符号组合 → 复合；未收录 → 未知，均保留原文
  - 可用性只按字典字段投影，未知与复合恒不可用
- [ ] 4. clean 房名规范化与节次展开
  - 全半角归一 → 反复删容量片段 → 压缩空白，保留方位/校区括号与原始名
  - 5 大节 → 12 小节，同一大节内各小节状态一致
- [ ] 5. pipeline 窗口与任务规划
  - 由当前周 C 与总周数 Y 求窗口 `C..min(Y,C+3)`；空窗 `skipped`
  - 每楼每周一条矩阵任务、每格至多一条占用说明任务；空白名单 `blocked`
- [ ] 6. pipeline 单轮互斥与过期收敛
  - 唯一索引保证同一时刻一轮；冲突时返回已有轮次
  - 启动时把超过 2 小时的 `running` 置为失败并记 `stale_run`
- [ ] 7. pipeline 执行循环与断点续跑
  - 从第一个 `pending` 继续，跳过 `done`，`failed` 不在本轮重试
  - 每任务完成即写 `collect_run_week`（含 `fetched_at` 与页面哈希）并回写轮次计数
- [ ] 8. pipeline 归属落库与冲突处理
  - 每楼响应内房号归属该楼，写 `room.building_id` 与当轮归属集合
  - 冲突按白名单顺序 + 周次升序取首个命中，后续楼该房号整行丢弃，一轮只记一次冲突
- [ ] 9. pipeline 失败分层与阶段推进
  - 必需失败 → 轮次 failed 且不发布；可选失败 → 继续并标 partial
  - 阶段字段按 登录 → 学期周历 → 周矩阵 → 占用说明 → 校验 → 发布 → 结束 推进
- [ ] 10. publish 候选集、派生与校验
  - 组装观测、说明与归属快照；按批写入单批 ≤5 万行
  - 派生只在窗口内、该房号该周无矩阵行时生成并标记
  - 候选集为空、必需任务未完成 → 拒绝发布并记录校验拦截；统计未知/复合
- [ ] 11. publish 单事务版本切换
  - 写 release（非 current）→ 观测 → 说明 → 归属快照 → 降原 current → 抬新 current → 删更早版本
  - 任一步失败整体回滚；成功后回写轮次汇总与 `release_id`
- [ ] 12. 检查点：一轮采集到发布端到端
  - 起库 + stubbed 上游，跑一轮到发布，再用公开查询验证
  - 全部测试与四条门禁通过；如有疑问询问用户
